用手机发送一句话，
让自己的电脑完成任务。

用户通过手机网页提交任务，在手机上查看电脑正在执行哪一步、最后得到什么结果，以及遇到问题后该怎样继续。

场景一：在 B 站搜索电影

输入“搜索电影”，电脑在 B 站搜索热门电影；输入“搜索个流浪地球”或具体片名，则搜索对应关键词。手机收到关键词、结果链接和截图，本版不自动播放视频。

场景二：操作腾讯会议

输入“加入腾讯会议，会议码 1234”或“创建一个腾讯会议”。系统检查输入和电脑环境；创建会议后核对实际会中状态并回传会议号。无效号码和权限问题分别给出处理提示。

会议码 1234 无法作为有效会议号完成入会。
腾讯会议的普通会议号为 9 位数字，个人会议号为 10 位数字。此输入应进入补充信息流程。打开客户端、下载页或加入页面，都不能作为成功入会的证据。腾讯会议官方说明

本次交付的判断标准

用户输入会生成真实任务记录；电脑有可观察的执行动作；手机持续显示状态；成功和失败都有原因；运营看板统计实际任务。只在检测到目标结果时将任务标记为成功。

本版范围为一台 macOS 电脑和同一局域网内的手机网页。电影流程已按用户反馈改为 B 站搜索，默认搜索和指定片名搜索均通过真实执行验证；腾讯会议自动创建也已完成验收。手机端使用浏览器手机视口验证，实体手机尚未实测。有效会议号入会和音视频状态仍需用户在电脑核对。

龙虾脑产品方案01 / 产品范围
USER VALUE目标用户与验证假设

先验证用户是否需要少操作几步

首批用户是假设中的两类人：电脑连接大屏、希望通过手机打开电影搜索结果的人；已经在电脑上准备参会、希望从手机发出入会或建会指令的人。两类用户都需要电脑保持在线，且已经完成必要的账号登录。

使用情况用户目前需要做的事情本版希望减少的操作需要验证的问题
电影搜索找到电脑、打开 B 站、输入片名并等待搜索结果。在手机输入搜索要求，由电脑打开对应结果。搜索词是否准确；结果是否载入；失败后是否知道怎样处理。
腾讯会议切到会议客户端、找到入口、输入会议号或创建会议、核对结果。从手机发出会议指令，在需要登录或补充会议号时收到明确提醒。能否节省操作时间；用户是否愿意授权电脑执行会议动作。

首次使用流程

1. 启动电脑服务电脑显示局域网地址和配对码，运行本机执行服务。
2. 手机完成配对连接同一 Wi-Fi，在网页输入电脑上显示的配对码。
3. 输入任务提交一句话，系统返回任务记录和当前状态。
4. 查看结果查看电脑的执行证据，或按提示补充信息后重试。

需要保留的用户控制

手机页应始终显示目标电脑。取消只能阻止后续步骤，无法撤回已发给腾讯会议的操作，执行器可能仍在执行该操作；页面或会议可能保留。创建会议后，手机会列出音视频检查结果，本次未自动确认这两项状态。共享屏幕与邀请他人由用户操作。

产品价值如何验证

让 5—10 位受邀用户分别手动完成任务和通过 Demo 完成任务，记录时间、操作次数以及是否仍需走到电脑前。拟定验证目标为：至少 7 / 10 位用户无需解释就能完成首次提交；在成功任务中，操作时间的中位数较手动流程减少 30%。这两个数字是验证门槛，尚无实测结果。

TASK EXPERIENCE任务状态与成功证据

让用户看到任务进行到哪一步

每个任务保留原始输入、解析后的操作、创建时间、状态变化与结果。任务进入需要处理或失败状态时，手机页面给出下一步操作。刷新页面后仍能看到此前任务。

状态用户看到的内容进入或结束条件
等待执行“任务已收到，前面还有任务正在执行。”服务接受输入并生成任务 ID；单台电脑逐个处理。
正在执行显示当前步骤，例如“搜索电影信息”或“检查腾讯会议”。执行器开始实际操作，每完成一步写入时间记录。
需要处理说明缺少的环境条件，例如“会议执行器缺少辅助功能权限，请在电脑授权后重试”。无法继续时停止操作，保留已有结果供用户核对。
执行成功显示实际结果、来源和核验信息。获得目标结果证据，不能只依据命令返回成功。
执行失败显示错误原因、已经完成的步骤，以及建议的恢复方式。输入无效、外部页面加载失败、执行工具报错或结果无法核验。
已经取消“已停止后续步骤，已经打开的页面可能仍保留。”收到取消请求后，执行器不再开始新步骤。

什么可以算成功

电影任务

电脑已经打开 B 站对应关键词的搜索结果，结果内容或明确的空结果提示能够读取。手机保留关键词、链接、当前页面结果数和截图。只打开页面或遇到验证时不能算成功；本版不核验视频播放。

会议任务

创建会议必须同时取得真实会中状态和当前会议号。未读到号码时保持需要处理，并提醒核对电脑。有效号码加入仍需人工确认；后续自动入会也须检测真实会中状态。

“搜索电影”默认使用“热门电影”关键词；指定片名时使用对应关键词，不受历史榜单范围限制。结果是否包含相关视频由 B 站决定，用户可在电脑继续选择；本版不自动播放视频。

ERRORS AND LIMITS异常处理与体验边界

每一种失败都需要有具体原因

情况手机反馈恢复方式
会议号为 1234“会议号需要 9 位或 10 位数字，当前只有 4 位。”用户核对邀请信息，补充完整会议号后重新提交。

有效会议号加入“请在电脑确认入会。”本版不自动完成加入。在客户端填写号码并核对密码、等候室和音视频选项。
页面加载失败“搜索页面未能正常打开，请检查电脑网络后重试。”保留原始输入，重新提交时创建新任务。

电脑睡眠或服务断开“与电脑的连接已断开，状态可能尚未更新。”唤醒电脑、启动服务并刷新手机页；避免盲目重复提交。
指令超出范围“当前支持电影搜索和腾讯会议，请重新输入这两类任务。”提供可编辑的示例，保留用户输入。

同一 Wi-Fi 下的配对限制

配对码只展示在电脑启动终端中；任务、结果和运营看板都需要完成配对后才能访问。服务只执行预设场景，不把用户输入拼成任意系统命令。配对会话有效期为 24 小时，服务重启后需重新配对。会议号和浏览器结果可能包含私人信息，录屏与对外演示应使用测试任务。

本地 HTTP 配对适用于受信任的局域网演示。正式产品需要 HTTPS、设备撤销、会话过期、权限分级和数据删除机制。不能把本版端口直接暴露到公共互联网。

未获得结果时保留失败或待处理状态04 / 异常与边界
OPERATIONS运营数据与指标口径

看板首先回答任务为什么没有完成

演示看板直接读取本机保存的任务，展示总量、状态分布、完成耗时、任务明细和错误原因。本版统计本机保留的全部任务，其中包含不同版本的验收任务。历史播放记录会继续保留，不能把这些演示数据当作正式用户增长数据。

当前指标实际计算方式如何理解
提交任务数本机所有已分配任务 ID 的记录数；同一个请求 ID 不重复创建任务。统计范围为当前保留的数据。
总体完成率成功任务数 ÷ 全部任务数，包括正在执行、需要处理及取消的任务。作为主指标，同时查看未完成状态分布。
终态成功率成功任务数 ÷（成功数 + 失败数 + 取消数）；需要处理的任务不进入此分母。必须显示分母，不能替代总体完成率。
平均耗时与 P95对有开始和结束时间的成功、失败、取消任务，统计执行结束时间 − 开始时间。不包含排队时间，也不包含需要处理的任务。
异常分布按错误代码统计所有含错误的任务，包括号码无效和环境不足。判断输入、环境和执行各占多少。
场景与近 7 天任务量分别按意图分组，以及按北京时间的创建日期分组；显示提交量与成功量。观察当前演示任务的组成。

试用阶段增加：端到端耗时中位数和 P95（接受时间至结束时间）、环境有效任务的执行成功率，以及补充信息后的恢复成功率。恢复成功率需按同一原始任务分组，使用已有的 retryOf 关联，分母为实际尝试恢复的任务组。

事件记录建议

本版使用任务状态和步骤日志生成看板。正式试用增加事件：task_submitted、task_started、step_completed、action_required、task_succeeded、task_failed、task_cancelled。每条事件带任务 ID、场景、时间和错误类别，不上传登录信息或页面全文。

不要把环境问题从主完成率中去掉。
未安装腾讯会议和无效会议号都会影响用户拿到结果。看板可以另设执行器成功率用于排查技术问题，但不能用它替代用户任务完成率。

本版已经保存重试来源，但尚未统计恢复成功率；真实用户留存、付费转化与满意度也尚未上线。文档中的建议门槛不是已经达成的成绩。

指标同时保留分子、分母和统计范围05 / 运营看板
IMPLEMENTATION实现选择与交付验收

用一个本地服务运行整条任务流程

手机网页通过局域网访问 Node.js 服务，负责配对、指令解析和任务记录。电影由 Tabbit 执行；会议通过 LaunchServices 启动已授权的 Swift 应用，以辅助功能的会中布局与首页“进行中”同一行会议号交叉核对结果。当前适配 macOS 14 以上、腾讯会议 3.46.0 的 720 × 480 首页，屏幕录制为可选项。

手机网页输入任务、查看步骤、读取结果、重试或取消。
Node.js 服务端口 8787，鉴权、解析和最多 5 个排队中或执行中的任务。
本机执行器Tabbit 操作浏览器；Swift 执行器操作会议窗口。
任务记录本地 JSON 保存任务；状态通过 SSE 与轮询返回手机和看板。

本版使用受限场景解析，覆盖约定表达和常见同义词。开发过程使用 AI 工具完成代码与验证；运行时不要求大模型 API Key。解析失败时说明范围，避免把无法识别的指令执行为系统命令。后续可以用语言模型提取结构化参数，但必须保留允许执行的操作列表和参数校验。

本地文件与执行结果可以复核06 / 实现与验收
MVP ROADMAP试用路径与后续投入

先提高两个场景的完成率，再扩大范围

阶段计划工作拟定进入下一阶段的条件
当前 Demo在一台电脑跑通手机指令、执行状态、结果反馈、异常提示与本地运营看板。B 站搜索与会议真实创建各完成一次；无效会议号与环境缺失准确返回；无虚构成功记录。
第一阶段
受邀试用		验证实体手机接入和重复创建的稳定性，补齐自动入会；招募 5—10 人试用配对、电影搜索和会议任务。在输入和环境有效的各 20 次任务中，每场景至少 18 次成功；所有失败均有原因；首次使用完成率至少 7 / 10。
第二阶段
连续使用		完善安装引导、重连、授权撤销、来源选择与重试分析；评估用语言模型解析更多表达；外网访问前完成安全设计。至少 100 个真实任务；整体完成率达到 85%；成功任务耗时 P95 少于 60 秒；每个未完成任务可定位原因。
第三阶段
有限扩展		依据用户重复使用的场景增加操作；按账号接入正式会议接口；完善升级、诊断与数据删除。前两场景保持稳定；新增场景有重复需求证据，并且可以定义可核验的成功结果。

腾讯会议的产品化接入

官方 MCP 已提供预约会议、查询会议详情等能力，可以作为后续创建会议的接入方式。接入需要用户授权；创建会议记录与驱动桌面加入会议是两项不同验收，不能混为同一个成功结果。腾讯会议 MCP 官方说明

优先投入与暂缓工作

首先投入执行结果核验、安装与登录检查，以及用户遇到失败后的恢复体验。多设备管理、语音输入、账号订阅和跨平台桌面支持应在两个场景反复使用后决定。当前没有收费转化或单位成本数据，不提出收入预测。

需持续关注的成本

每个场景记录开发维护时间、执行耗时、失败排查时间和外部 API 费用。若以后引入语言模型，单独记录每次任务的模型调用成本，并比较它对解析成功率的实际提升。

所有阈值均为本项目提出的试用目标，时间与资源应在第一轮试用后调整。产品方案中的事实引用已于 2026 年 10 月 21 日核对官方页面。
